# Repo Audit — 2026-11-15

Audit of `main` at `cc82b9b` (after PR #3). Assumed load: one person on one machine, one process, one `generate` call at a time. Findings 1 and 4 were reproduced by running them. The test-coverage claims were checked with mutation testing: bugs injected into a scratch copy of the kernel.

Tick items off as they land; note the commit next to each.

## Must fix

- [x] **1. `generate` writes past the caller's buffer** — fixed on `fix/c-api-hardening`: `Engine::validateRequest` rejects bad input before anything is written; `generate` returns the count written, or -1 (`engine/engine.cpp` prompt copy and loop bound; `engine/engineAPI.cpp`)
  - **Problem:** Nothing checks the sizes.
    - A prompt longer than `max_tokens` is copied anyway. Reproduced: a 30-token prompt with `max_tokens=24` overwrote slots 24–29 past the end of the buffer.
    - `max_tokens > 1024` reads past the 1024-row position-embedding table (`wpe`).
    - `max_tokens = 0` makes `maxTokens - 1` wrap around to about 4 billion.
    - Token IDs ≥ 50257 read past the token-embedding table (`wte`).
  - **Fix:** At the top of `generate`, return early unless `1 <= prompt_len < max_tokens <= 1024` and every token ID < 50257. Also give the caller a way to know how many tokens were written (see the note under finding 1 below).
  - **If skipped:** A long prompt typed into the frontend corrupts Python's memory.

- [x] **2. `init_engine` returns a garbage pointer on failure** — fixed (`b3f1925`) (`engine/engineAPI.cpp`)
  - **Problem:** `Engine *engine;` is never initialized. If the constructor throws (for example, missing weights), an uninitialized pointer is returned, and the next `generate` crashes.
  - **Fix:** `Engine *engine = nullptr;`. Then check for null in Python (ctypes returns `None` for a null `c_void_p`).

- [x] **3. A full arena crashes the process instead of failing cleanly** — fixed: `alloc` throws `std::bad_alloc`, and the arena is sized per request from `Engine::stepArenaBytes` (`engine/core/arenaAllocator.cpp` `alloc`)
  - **Problem:** When the arena is full, `alloc` prints "Out of memory" and returns `nullptr`, and every caller writes through it. Prompts of about 192 tokens or more crash (about 200 with a 100 MB arena).
  - **Fix:** Throw `std::bad_alloc` (or abort with a message) instead of returning `nullptr`. Finding 5 also cuts how much memory prompt processing needs.

- [ ] **4. `topK = 0` crashes when sampling** (`engine/models/transformer.cpp` `getTopKIndices` / `sampleTokenIdx`)
  - **Problem:** With temperature > 0 and `topK = 0`, the kept list is empty and `keptIndices.back()` reads from an empty vector. Reproduced: segfault, exit code 139.
  - **Fix:** Treat `topK == 0` (or `topK > vocab`) as the vocabulary size.

## Should fix

- [x] **5. Prompt processing computes and softmaxes logits for every prompt token** — fixed (`7845889`) (`engine/engine.cpp` LM-head projection; `transformer.cpp` `sampleTokenIdx` TODO)
  - **Problem:** Only the last row picks the next token. At 128 tokens, the full LM head takes ≈250 ms of the ≈667 ms time to first token, plus ≈25 MB of arena. Sampling also runs softmax over all N rows.
  - **Fix:** Compute the projection for the last row only, as a one-row view of `normX`.

- [ ] **6. The weights file is trusted without checking its size** (`engine/models/engineHelpers.cpp` `buildModel`; `engine/core/modelWeightsLoader.cpp`)
  - **Problem:** Nothing checks `offset + elements × 4 <= file size`. A truncated `.bin` (an interrupted `make weights`) next to an old `.json` reads past the end of the mapping, giving a bus error or wrong output.
  - **Fix:** Keep the file size in `ModelWeightsLoader`, check each tensor in `buildModel`, and throw on mismatch.

- [ ] **7. The thread pool can hang at process exit** (`engine/core/taskQueue.cpp` destructor)
  - **Problem:** `stopThreads_` is set without holding `tasksMutex_`. A worker that has checked the flag (false) but not yet gone to sleep misses the `notify_all` and sleeps forever, so `join()` hangs. This is the same lost-wakeup pattern as the earlier task-submission fix.
  - **Fix:** Set `stopThreads_` while holding `tasksMutex_`.

- [ ] **8. Sampling has no tests and can't be tested** (`engine/models/transformer.cpp` temperature / top-K / top-P)
  - **Problem:** All tests and benchmarks use greedy decoding, so this code never runs in CI (that's how finding 4 slipped through). It also builds a new `std::random_device` and `mt19937` every token, so results can't be reproduced.
  - **Fix:** Seed one generator once, with an optional fixed seed. Add a unit test of `getTopKIndices` / `applyTopPFiltering` on a small hand-made logits row, including `topK = 0` and `topP` edge cases.

- [ ] **9. The ctypes binding is copy-pasted four times** (`frontend/frontend.py`, `tests/e2e/test_greedy_decoding.py`, `tests/e2e/test_synthetic_regression.py`, `bench/e2e_bench.py`)
  - **Problem:** Each file declares the `init_engine` / `generate` signatures. A change to the C API must touch all four, and a missed copy silently passes wrong argument types.
  - **Fix:** One small `engine_api.py` that loads the library, sets the signatures and exposes `generate(prompt, max_tokens, ...) -> list`, imported by all four (about −60 lines).

- [ ] **10. `OpAttrs` and the attribute structs are unused, and duplicate the operator classes** (`engine/ops/opType.hpp`)
  - **Problem:** Nothing in the tree uses `OpAttrs`, `LayerNormAttrs`, `MatMulAttrs` and the rest. The `Operator` classes store the same values again (`eps_`, `transposeA_`, …), so defaults live in two places.
  - **Fix:** Before Phase 2, keep one representation and delete the other (about −35 lines).

## Nice to have

- [ ] **11. GELU runs in double precision** (`engine/ops/mathOps.cpp` `gelu_out`)
  - **Problem:** The `0.5` / `1.0` / `0.044715` literals and `tanh` are double precision. That costs ≈3.3 ms per layer at 128 tokens, ≈40 ms of prompt processing.
  - **Fix:** Float literals (`0.5f`) and `std::tanh` on a float.

- [ ] **12. `appendK`/`appendV` and `getK`/`getV` are near-copies** (`engine/models/KVCache.cpp`)
  - **Fix:** One `append(layer, slot, pos, view)` and one `get(layer, slot, len)` (about −25 lines). Worth doing during the KV-caching phase.

- [ ] **13. Stale and dead files**
  - `scripts/model_convertor_nb.ipynb` is an older copy of `convert_weights.py`. Delete it.
  - `.vscode/launch.json` launches `bin/engine`, which the Makefile no longer builds. Remove that entry.
  - `engine/ops/mathOps.cpp` includes `arenaAllocator.hpp`, and `mathOps.hpp` forward-declares `ArenaAllocator`; neither is used. Remove both lines.

## Notes from the first attempt at finding 1 (2026-11-15) — all resolved on `fix/c-api-hardening`

- **Off-by-one in the decode loop, which broke `make test_full`.** Renaming `currSize = prompt.size() - 1` to `nextTokenIdx = prompt.size()` changed what the loop variable means, but the decode branch still uses it as "the index of the newest known token":
  - The first decode step reads `prompt[tokenIdx]`, one past the end of the vector, and embeds it at a position one too far.
  - The loop runs one fewer time, so the last output slot is never written. It stays 0, which decodes to `"!"`.
- **The `prompt_len >= max_tokens` check doesn't validate anything yet.** Both branches copy the whole prompt.
- **The new `<|endoftext|>` (50256) early stop leaves the remaining output slots unwritten**, and `generate` returns `void`. The caller can't tell how many tokens are real, and decodes the leftover zeros as `"!!!"`. Return the generated length, or write a sentinel.
- **The frontend now allows `max_tokens = 256`**, but prompts of about 200+ tokens still overflow the 100 MB arena (finding 3).
